Swift — Summary of the Grammar

// SWIFT 6.3 GRAMMAR
// swift-syntax parseSourceFile (TopLevel.swift:47) consumes an optional leading `.shebang`
// (`#!…` interpreter line) before the top-level items. `shebang?` appears only here, in the
// root production at offset 0, and `#!` is not valid Swift anywhere else, so it can only match
// a true leading shebang. `.*` stops at end of line; the newline is then whitespace trivia.
// `shebang` must be defined before it is referenced (named terminals require prior definition).

Grammar of shebang ‹token terminal›

shebang → /#!.*/

Grammar of top-level-declaration

top-level-declaration → shebangopt statementsopt

Grammar of whitespace ‹discarded terminal›

whitespace → /[\u{0000}\u{0009}\u{000A}\u{000B}\u{000C}\u{000D}\u{0020}\u{FEFF}]+/

// non-ASCII whitespace generates a warning e.g. a  + 2

Grammar of comment ‹discarded terminal›

comment → /\/\/.*\r?\n?/

Grammar of multiline-comment ‹trivia rule›

multiline-comment → /* (/(?s)(?:[^*\/]|\*(?!\/)|\/(?!\*))+/ | multiline-comment)* */

Grammar of identifier ‹token terminal› ‹@lexicalClass›

identifier → @builder

Grammar of escaped-identifier ‹token terminal›

escaped-identifier → /`[^`\\\u{0000}-\u{001F}\u{007F}\u{0085}\u{00A0}\u{1680}\u{2000}\u{2001}\u{2002}-\u{200A}\u{2028}-\u{2029}\u{202F}\u{205F}\u{3000}]+`/

Grammar of string-literal

string-literal → static-string-literal | interpolated-string-literal

Grammar of single-line-string-literal ‹token terminal›

single-line-string-literal → /"(?:[^"\\\n\r]|\\u\{[0-9a-fA-F]+\}|\\[0\\tnr"']|\\(?!\().)*?"/

// start with " end with " same line, no \(

Grammar of extended-singleline-string-literal ‹token terminal›

extended-singleline-string-literal → /(#+)"(?:[^"\n\r]|"(?!\1))*?"\1/

// backref: closing #s must equal opening

Grammar of multiline-string-literal ‹token terminal›

multiline-string-literal → /"""(?![\s\S]*\\\()(?:[^"\\]|\\[\s\S]|"(?!""))*"""/

// start """ end """; body's `\<x>` uses `[\s\S]` so `\<NL>` (multiline line-continuation per swift-syntax Cursor.swift:1766) is body content; lookahead uses `[\s\S]` so it crosses newlines

Grammar of extended-multiline-string-literal ‹token terminal›

extended-multiline-string-literal → /(#+)"""[ \t]*\r?\n(?s:.)*?"""\1/

// backref: closing #s must equal opening. `[ \t]*\r?\n` after the opening `#"""`: swift requires a multiline opener to be followed by a newline (Cursor.swift advanceIfMultilineDelimiter). Without it, `#"""…"""#` is a SINGLE-line raw string with `"` content ("false delimiters" — probe: `#""""""#` → stringQuote, not multilineStringQuote), which resolves the extendedSingleline-vs-extendedMultiline ambiguity on quote-only raw bodies.

Grammar of static-string-literal

static-string-literal → single-line-string-literal | extended-singleline-string-literal | multiline-string-literal | extended-multiline-string-literal

Grammar of interpolated-string-literal-head ‹token terminal›

interpolated-string-literal-tail → /\)(?:[^"\\\n\r]|\\u\{[0-9a-fA-F]+\}|\\[0\\tnr"']|\\(?!\().)*?"/

// start with ), end with " same line, no \(

Grammar of multiline-interpolated-string-literal-head ‹token terminal›

multiline-interpolated-string-literal-head → /"""(?:[^"\\]|\\u\{[0-9a-fA-F]+\}|\\[0\\tnr"']|\\[\s\S]|"(?!""))*?\\\(/

// start with """, end with \(

Grammar of multiline-interpolated-string-literal-part ‹token terminal›

multiline-interpolated-string-literal-part → /\)(?:[^"\\]|\\u\{[0-9a-fA-F]+\}|\\[0\\tnr"']|\\[\s\S]|"(?!""))*?\\\(/

// start with ), end with \(

multiline-interpolated-string-literal-tail → /\)(?:[^"\\]|\\u\{[0-9a-fA-F]+\}|\\(?!\()[\s\S]|"(?!""))*?"""/

// start with ), end with """; body's `\<x>` (x ≠ `(`) uses [\s\S] so `\<NL>` is body content
